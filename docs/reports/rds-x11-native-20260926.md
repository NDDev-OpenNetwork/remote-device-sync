# X11 input and capture qualification — 2026-09-26

Scope: W6.4/W6.8 increment; no wave, performance or release gate is closed.
Code source: `0c14adddf76711a6992f34d7425c2bbf464cb14e`.
See the [native input contract and reproduction command](../x11-input.md).

Four regressions failed on the preceding implementation: evdev KEY_A did not
press X keycode 38, evdev mouse buttons did not press the expected native button,
relative motion replaced the pointer position, and an isolated scroll request
never arrived without another input event. The Rust XTEST/core backend now maps
codes explicitly, checks native requests, preserves fractional scroll, and uses
the native relative-motion flag. Absolute motion targets the selected root;
input and capture reject nonexistent screens instead of selecting another one.

The sink tracks its injected holds and attempts release on teardown. A native
regression exposed that flushing and immediately closing the X connection did
not reliably release them; a final server roundtrip keeps the connection alive
through release delivery. Native calls still run in the blocking worker and may
complete after asynchronous cancellation.

  the BGR bytes of a known painted pixel.
- After the final capture-fixture change, scoped X11 clippy passed. One complete
  native run and a fixed three-run qualification batch passed: 28 native test
  executions, zero failures, no per-test retry or increased deadline.
- The workflow's folded test command was parsed and checked with `bash -n`.
  Linux CI requires the native lane after workspace tests; unavailable native
  setup is an error. GitHub Linux/macOS integration results are independent of
  these local results.

An earlier native fixture run failed while opening an observer connection:
Xvfb reset when its last client disconnected between tests. The dedicated server
now uses `-noreset`; the fixed qualification batch checks this fixture change.
Ordinary tests no longer repaint or inject into an ambient developer desktop.
Xvfb is test infrastructure only, not a product runtime dependency.

## Limits and remaining work

This verifies two X screens with the standard Linux XKB evdev map. It does not
qualify RandR monitors, dynamic geometry, custom layouts/IME, extended keys,
composited desktops, Wayland, macOS or physical devices. Input ACK means native
backend acceptance, not visible application response; there is no new latency
measurement or input-to-visible claim.

Focus/pointer checks are non-atomic admission checks. XTEST shares the local
seat; controller exclusivity, local-input interaction and consent remain open.
Release is best effort on native connection failure. Managed viewer/rendering,
desktop wire session IDs, native memory budgets and real-network acceptance
remain in the remediation plan. No installed agent or published release changed.
