# Directory HTTP framing — 2026-09-24

Scope: the W1.5 HTTP framing step after admission commit `e46125f`.
No deployment or wave closure. All fixtures use synthetic identities and loopback.

## Reproduced before implementation

Seven new regression cases failed against `e46125f`; `http-before.log` retains
the failure output in the private audit evidence:

- Duplicate Content-Length fields were accepted, including conflicting lengths.
- The response parser ignored Transfer-Encoding.
- Malformed versions, status lines and header syntax were accepted.
- HTTP/1.1 requests did not require Host, and responses without an explicit
  body length defaulted silently to an empty body.
- A head terminating at 8193 bytes passed the nominal 8192-byte limit.
- Outgoing method/path injection and oversized bodies were not refused before
  emission.
- A real directory accepted and stored a valid signed publication wrapped in
  an ambiguous request with two different body lengths.

These are parser/control-plane defects. The loopback evidence does not assert
that a particular deployed proxy was exploitable or that an estate was attacked.

## Implementation

One shared header grammar validates both directions; the request and response
start lines have explicit bounds and supported versions/statuses. Duplicate
lengths (even equal), Transfer-Encoding, unsupported compression/expectations,
invalid Host authorities and malformed fields are refused before body parsing.
Body/head size limits are enforced on reads and before writes. A 1 KiB buffer
avoids one underlying socket read per head byte without losing prefetched body
bytes. No dependency or external runtime helper was added.

The service closes after one exchange and never routes a second pipelined
request. Parsed HEAD requests receive no response body, including when workers
are saturated. Bodyless 204/304 responses obey their special length semantics.
This remains a restricted private Content-Length API, not a general HTTP stack;
the [profile](../record-state.md#directory-http-profile) lists compatibility
limits. Proxy/tunnel interoperability requires its own qualification.

## Additional coverage

The final framing target has eleven tests, with tables of rejected variants:
both parsers; exact head/body boundaries; truncated messages; writers that emit
no bytes on invalid input; the real signed PUT regression; a real client facing
ambiguous replies with otherwise valid signed records; a maximum 256 KiB binary
body fragmented through a seven-byte duplex stream; and connection closure
after a pipelined extra request. The worker ownership test also checks a
bodyless HEAD refusal while a timed-out blocking job still holds its permit.
Existing arbitrary-byte parser properties, TLS failures/timeouts, signed
policy/record persistence and publisher/owned-relay tests remain in the matrix.

The first expanded test build caught an incorrect test-only Client import;
the import was corrected without changing the public API or suppressing lints.
The eleven framing tests then passed. This is regression evidence, not a
production latency measurement or coverage-guided fuzz campaign.

The first all-feature network/agent/relay run exposed an existing expiry-fixture
race: a one-second record expired before an assertion that a fresh GET must
succeed. The fixture now checks successful resolution with a 300-second record,
then publishes a five-second successor (longer than the single PUT deadline)
and waits for its signed expiry boundary. It still requires both a real-directory
410 and independent resolver rejection of those expired bytes returned in a
hostile HTTP 200. There is no retry of a failed assertion or production grace
period. The original failure is preserved in `http-checks/owned.log`.
