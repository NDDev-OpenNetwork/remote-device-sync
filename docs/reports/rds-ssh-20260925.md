# RDS native SSH client and standard PTY

Date: 2026-09-25. Scope: W5.1/W5.3/W5.5 partial, with W10 telemetry integration.
Baseline: `14dcb79e1cb9091bc902eeef505aca0784eb3d14`. This is local Linux
implementation/interoperability evidence, not a complete W5 checkpoint,
deployment receipt, latency measurement or release qualification.

## Result and dependency decision

The new `rds-ssh` library uses exactly russh 0.63.3 over an owned async byte
stream. RDS retains peer/session selection, host trust, cancellation, resource
policy and terminal restoration. SSH messages and key formats belong to russh;
PTY allocation belongs to the remote OS through RFC 4254. No product command
launches an SSH executable, terminal helper or local shell.

`rds ssh` and `rds session ssh` now run a shell or an explicit exec command.
The old local listening-port behavior moves to `rds forward`. Managed SSH pins
one session ID and opens a TCP stream through the running agent, without another
endpoint identity or UDP socket. Explicit direct mode supports the same SSH
options. The existing IPC-v2 OpenTcp and remote RDS wire formats are unchanged.

The client requires an explicit account, trusted public host-key file and either
a private authentication key or one selected key from a local SSH agent. It
rejects changed host keys before authentication, never enumerates/falls back to
other agent identities, and refuses unsolicited server channels. No agent
forwarding, automatic host-key acceptance or command replay is introduced.

The russh dependency enables only its `ring` backend; RSA, DSA and compression
features are disabled. This reuses an existing native crypto boundary and does
not claim a literally all-Rust dependency graph. The controlled device still
needs an independently configured SSH server such as OpenSSH. A privileged
Rust account broker is not part of this increment. See the
[contract and migration examples](../ssh.md) for exact algorithms, file trust,
timeouts, buffering, terminal and exit semantics.

## Failure-driven regression evidence

- Strict host-key verification precedes user authentication. Authentication,
  PTY and exec rejection close the owned transport; missing exit status fails.
  Key-file permission, symlink, FIFO and size/type checks precede key use.
- Full-duplex traffic larger than the advertised SSH window crosses a 4 KiB
  underlying stream byte-exactly, including split UTF-8. An earlier 16 KiB
  transport bridge deadlocked because the protocol runner flushed writes while
  its peer also awaited read progress. The final bounded 512 KiB bridge in each
  direction provides headroom for the advertised 256 KiB receive window.
  This is a regression result, not a general hostile-peer memory bound.
- Upload and output draining progress concurrently. A remote command may exit
  before reading all stdin; its status and trailing stdout/stderr survive.
  Receiving an exit status does not truncate output before channel close.
- Cancellation during banner/KEX and blocked output closes the actual stream
  independently of the upstream runner's task lifetime. Setup deadlines are
  bounded; an idle responsive shell survives multiple keepalive intervals.
  No automatic reconnect repeats an exec command.
- A real local OS PTY exercises raw-mode and descriptor restoration, shared
  standard-descriptor flags, PTY rejection, external SIGTERM and resizing.
  Typed control bytes travel to the remote PTY. Externally delivered signals
  cancel the local session; local suspend/resume is not implemented.
- Real CLI processes use the managed RDS path, preserve status 23 and separate
  output bytes, reuse one underlying connection, and avoid creating another
  identity. The feature-expanded lane also exercises the owned Noq transport.
- A deliberately forged schema-valid RDS event in remote stderr remains only
  command output. JSON-mode SSH requires an exclusive private `--log-file`
  before any connection. Its writer rejects unsafe paths/existing entries and
  caps each process file at 8 MiB. Terminal console logging uses a cancellable,
  acknowledged pause barrier; file-backed telemetry continues during a TUI.
- An opt-in reference OpenSSH test uses disposable synthetic host/user keys,
  isolated configuration and a temporary SSH-agent socket. It verifies native
  key and selected-agent authentication, separate command output/status and a
  real server PTY with the requested size. It does not edit installed SSH
  configuration or load an operator's real authentication keys.

The fixed `ssh_connect` and `ssh_session` operation names are accepted by both
Rust and Vector projections. They contain no account, command, key, path or
terminal content. A completed SSH session can contain a nonzero command status;
the operation outcome describes protocol completion, not command success.

## Remaining acceptance work

W5 stays partial. Required work includes GDS-signed SSH host-key provisioning
and rotation, account/command-scoped grants, a qualified Rust account broker,
authorized process survival/PTY reattachment and bounded history. Lease renewal
and revocation must be exercised through multi-hour mixed SSH/video/sync runs.
Native macOS execution, real relay/NAT/path changes, slow consumers, resource
budgets and connection latency remain unqualified. The test harness here uses
loopback/synthetic fixtures; no physical WAN or performance claim follows.

Host certificates, RSA, password/keyboard-interactive authentication and MFA
are outside the implemented client policy. Direct private-key authentication
accepts unencrypted keys; encrypted keys use an explicitly selected local agent
key. Current RDS authorization covers the SSH TCP destination; target-account
authorization is still enforced by the existing remote SSH server.

Viewer/sync manager APIs, interactive desktop and platform backends, recursive
sync, GDS lifecycle, transport campaigns and O2–O6 observability work retain
their existing gates in the [completion plan](../remediation-plan.md).
No whole W0–W10 wave closes, no checkpoint/benchmark is substituted by unit
tests, and no running service or production observability pipeline is changed.
